# Incident Analysis: Stale Translation Cache

## Incident Summary

Text translation requests returned outdated, incorrect results even though the current IndicTrans2 models and direction routing produced correct output when invoked directly. The issue was most visible for Hindi-to-English, Marathi-to-English, Hindi-to-Marathi, and Marathi-to-Hindi requests.

- Date validated: 2026-09-08
- Validation run: Test Run 8
- Application: Samvaadhika 1.0.0
- Tested commit: `5d83ae8acc97d91960e293247c3e27eab85d8dae` with the local translation corrections under test
- Browser target: `http://127.0.0.1:8000`
- Result: 35 of 37 cases passed (94.6%)

## Impact

Users could receive a previously cached translation generated by an older model path or routing implementation. The response appeared successful and displayed the cached indicator, but its language or script could be wrong. This made healthy model installations look broken and affected confidence in reverse and cross-Indic translation.

Observed before correction:

- Hindi-to-English results remained in Hindi.
- Marathi-to-English results remained in Marathi.
- Hindi-to-Marathi and Marathi-to-Hindi results could remain in the source language or become incoherent.
- Corrected model behavior was hidden by historical database rows.

## Root Cause

The text cache key was derived only from source language, target language, and input text. It did not identify the translation pipeline version.

Consequently, changing model routing, preprocessing, decoding, or postprocessing did not invalidate earlier cached rows. Requests matching old text and language pairs reused stale `Job` records instead of invoking the corrected pipeline.

The model files were not the root cause. All three IndicTrans2 checkpoints were present, and direct uncached inference returned the expected target languages.

## Resolution

The cache key now includes an explicit translation pipeline version:

```text
indictrans2-v2:<source-language>:<target-language>:<text>
```

This creates a new cache namespace while preserving historical job and audit records. No destructive database cleanup is required.

Related corrections validated in Test Run 8 include:

- Direction-specific routing for English, Hindi, and Marathi.
- Reuse of loaded tokenizer/model instances.
- Thread-safe inference for shared tokenizer state.
- Five-beam decoding.
- URL and line-break preservation.
- English punctuation preprocessing.
- Curated semantic handling for the two tested non-compositional idioms.
- Protection against transliterating clean English when both ASR and detection identify English.

## Verification

Test Run 8 confirmed that the previously stale-cache-affected directions now return correct fresh results:

| Case | Direction | Result |
|---|---|---|
| TT-03 | Hindi to English | `My name is Mohit.` |
| TT-04 | Marathi to English | `My name is Mohit.` |
| TT-24 | Hindi to Marathi | `तुमच्याकडे शाकाहारी अन्न उपलब्ध आहे का?` |
| TT-36 | Marathi to Hindi | `मेरा नाम मोहित है ।` |
| TT-37 | Hindi to Marathi | `माझे नाव मोहित आहे.` |

TT-14 also verified normal cache behavior: the first submission was uncached and the identical second submission returned from cache. TT-21 verified that a fresh cache entry survived a real Uvicorn restart.

## Remaining Risk

Two failures remain, neither caused by stale cache:

1. TT-09: an accepted 10,000-character request blocked the UI and server for more than 240 seconds.
2. TT-28: the amount and currency were retained, but Devanagari digits `१२३` changed to ASCII `123`.

These are documented separately in `test-failure-details.md`.

## Prevention

- Increment the translation pipeline version whenever model routing, checkpoints, preprocessing, decoding, postprocessing, or curated overrides change.
- Keep cache regression cases for fresh-to-cached behavior and restart persistence.
- Test direct uncached inference before diagnosing model installation problems.
- Preserve historical jobs; invalidate behavior through versioned keys rather than deleting audit data.
